# 高项电竞社 · 设计文档

日期：2026-11-15
状态：已与用户确认设计方向，待评审

## 1. 目标与背景

为用户本人开发一款自用的软考高项（信息系统项目管理师，2027 年上半年考试）备考软件。通过轻量小游戏合集提升学习积极性，在软件帮衬下通过考试。

已确认的关键决策（来自需求澄清）：

| 决策点 | 结论 |
|---|---|
| 用户基础 | 零基础，从头开始，软件需带学知识点 |
| 科目覆盖 | 三科都担心；V1 以综合知识（客观题）游戏化为主，案例计算题以数值选项形式并入，论文练习器留 V2 |
| 使用场景 | 手机碎片时间 + 电脑整块时间，同一套文件 |
| 游戏形态 | 方案 D 轻量小游戏合集（用户在 B 经营模拟 / C 卡牌对战间也有兴趣，V2 可叠加元素） |
| 技术形态 | 纯静态 Web，无框架、无构建、无后端，file:// 双击可用 |
| 题库来源 | 先由 AI 按教程第 4 版章节体系内置生成，后续用户可导入材料扩充 |
| 视觉风格 | 绝区零式「街头电光」：纯黑底 + 荧光绿/橙 + 斜切面板 + 粗斜体；拒绝 emoji 图标与通用蓝渐变 |

## 2. 产品结构

单页应用，5 个导航区（手机底部 Tab / 电脑加宽布局）：

1. **今日** — 任务中心：考试倒计时、每日打卡任务、连胜状态、章节掌握度摘要
2. **游戏厅** — 5 款游戏入口
3. **街区** — 章节地图：按教程章节推进，每章显示掌握度，Boss 战通关解锁下一章
4. **错题** — 错题回收站：间隔重复到期队列与记忆度
5. **档案** — 数据看板 + 存档导出/导入 + 设置

## 3. 游戏设计（5 款）

| 游戏 | 玩法 | 玩法细节 | 针对考点 |
|---|---|---|---|
| 考点歼灭 | 答题战斗 | 章节选择 → 10 题一局；答对攻击怪物（连击 ×3 起加成），答错扣自身 HP；结算掉落经验 | 全题型单选，含 EMV/挣值/关键路径等计算题（数值选项） |
| ITTO 分拣 | 限时分拣 | 60 秒内把卡片拖/点入「输入 / 工具与技术 / 输出」三栏，错拣扣时 | 49 过程 ITTO 记忆 |
| 术语配对 | 翻牌配对 | 4×4 棋盘，术语↔定义翻牌，配对成功消除 | 零碎概念（术语、缩写、定义） |
| 流程接龙 | 步骤排序 | 乱序流程步骤，点击按正确顺序排列，错序重置当前步 | 变更控制/风险应对/立项验收等流程 |
| 街区 BOSS 战 | 章节综合测验 | 每章 30 题限时（约 25 分钟），及格线 60% 通关，通关解锁下一章 | 阶段性自测 + 地图推进 |

游戏命名与文案统一使用绝区零式街头语言（如「考点歼灭」「错题清扫」「街区」），不用 emoji 做图标。

## 4. 学习系统

- **每日任务**：每日 4 项 = 3 款小游戏（考点歼灭必含）+ 错题清扫（到期数量）；完成 3 项视为打卡成功
- **连胜（STREAK）**：当日完成 ≥3 项任务即延续；「连胜冻结」每月 2 张，漏卡当日自动消耗
- **错题本 + 间隔重复**：答错自动入库；复习周期 1→2→4→7→15 天；答对一次推进周期，答错回落至 1 天；每题维护记忆度（0-100%）
- **掌握度**：章节掌握度 = 该章题目加权正确率（新题 70% + 复习题 30%），Boss 战通关额外 +10% 封顶 100%
- **倒计时**：考试日期默认 2027-05-22（按 2027 上半年惯例预估，可在设置中修改）

## 6. 技术架构

```
gaoxiang-game/
├── index.html          # 单页应用外壳，按 script 标签顺序加载（非 ES modules，保证 file:// 可用）
├── css/style.css       # 设计系统 + 布局（手机优先，≥768px 加宽）
├── js/
│   ├── app.js          # hash 路由、全局状态、存档（localStorage）、每日任务/连胜/间隔重复调度
│   ├── games/
│   │   ├── monster.js  # 考点歼灭
│   │   ├── itto.js     # ITTO 分拣
│   │   ├── match.js    # 术语配对
│   │   ├── chain.js    # 流程接龙
│   │   └── boss.js     # 街区 Boss 战
│   └── data/
│       ├── bank.js     # window.BANK 题库（分章、分题型）
│       └── meta.js     # 章节结构、ITTO 表、流程步骤数据
```

约束与决策：

- **零依赖**：原生 JS/CSS，不用框架、构建工具、CDN、字体文件；离线可用
- **file:// 兼容**：不用 ES modules 与 fetch 加载本地 JSON；题库以 `window.BANK` 全局变量提供
- **存档**：localStorage 单键 `gaoxiang_save`；「档案」页提供导出/导入 JSON（换设备/防清缓存）
- **响应式**：手机竖屏优先（≤480px 单列），≥768px 双栏/加宽

## 7. 数据模型

题库条目（bank.js）：

```js
{ id:"c2q001", ch:2, type:"single|itto|match|chain",
  q:"题干", opts:["A","B","C","D"], ans:0, exp:"解析",
  tags:["风险"], diff:1-3 }
// itto 型: { card:"风险登记册", cat:"output|input|tool", process:"识别风险" }
// chain 型: { steps:["提交变更申请","CCB评审","批准/拒绝","更新基线"] }（顺序即正确答案）
// match 型: { pairs:[["CPI","成本绩效指数"],...] }
```

存档（localStorage）：

```js
{ version:1,
  streak:{ count:7, last:"2026-11-15", freezes:2 },
  daily:{ date:"2026-11-15", tasks:{monster:true, itto:false, ...} },
  chapters:{ 1:{mastery:82, bossCleared:true}, ... },
  wrong:[{ qid:"c2q001", count:3, next:"2026-11-16", mem:66 }],
  stats:{ totalAnswered:0, correct:0, byChapter:{...} },
  settings:{ examDate:"2027-05-22" } }
```

## 8. 题库计划

- 章节体系对齐《信息系统项目管理师教程》（第 4 版）：信息技术知识（1-5 章）+ 项目管理十大知识域与过程（6-20 章）+ 法规标准/职业道德（21-24 章）；十大知识域按过程组展开 ITTO 数据
- 每章配 30-60 题（single 为主）+ 每知识域 ITTO 卡片集 + 每章术语配对集 + 核心流程接龙集
- V1 内置第 1-24 章框架，题目分里程碑逐步入库；用户后续提供真题/材料时由 AI 转换为 bank.js 格式导入

## 9. 里程碑

| 里程碑 | 交付 | 验证点 |
|---|---|---|
| M1 | 框架 + 今日页 + 考点歼灭 + 连胜 + 错题本 + 第 1-3 章题库 | 「学→玩→错题→复习」完整闭环可跑 |
| M2 | ITTO 分拣 + 术语配对 + 流程接龙 + 街区地图 + 第 1-10 章题库 | 4 款游戏可切换，章节推进可用 |
| M3 | Boss 战 + 档案看板 + 导出/导入 + 全 24 章题库 | 备考主力工具成型，进入日常使用 |

每个里程碑交付后在浏览器实测验收。

## 10. 范围外（V2 候选）

- 论文练习器（题库+提纲+范文卡）
- 卡牌收集层 / 经营事件层（用户在风格选型中对 B/C 表达过兴趣）
- 案例分析主观题批改、AI 讲解（需联网/模型接入）
- 多设备云同步（V1 用导出/导入替代）

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| localStorage 被清理导致进度丢失 | 每次结算自动提示周期性导出；导入恢复 |
| 内置题库与真题偏差 | 间隔重复只依赖题级数据，可随时扩充/替换 bank.js |
| 游戏新鲜感衰退 | M3 后按使用数据迭代（卡牌层/Boss 进化）；连胜冻结机制保底留存 |
| file:// 下 Safari 兼容差异 | 以 Chrome/Edge 为主要验证目标，Safari 若异常则用本地 http 服务 |
