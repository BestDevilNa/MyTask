## 数据模型

```js
window.GX_CASE = {
  version: 1,
  domains: [
    { key: "scope", name: "范围管理", ch: 5 },
    // 进度6 成本7 质量8 资源9 沟通10 风险11 采购12 干系人13 整合4
  ],
  cases: [{
    id: "cs001",
    domain: "scope",
    ch: 5,
    title: "需求蔓延的智慧园区项目",
    bg: "……案例背景（200-400 字）……",
    questions: [
      {
        id: "cs001q1",
        type: "find",              // find 找错 / measure 措施 / calc 计算
        q: "指出该项目在范围管理上存在的问题。",
        points: ["未制定范围管理计划", "需求未经变更控制", "缺少验收标准"],
        answer: "参考答案（成段表述）",
        exp: "采分点说明"
      },
      {
        id: "cs001q2",
        type: "calc",
        q: "计算当前 SPI 与 CPI。",
        answer: { value: 0.8, unit: "SPI", tol: 0.01 },   // 可多空
        steps: ["EV=…", "PV=…", "SPI=EV/PV=0.8"],
        exp: "结论：进度落后、成本超支"
      }
    ]
  }],
  byDomain: function (key) { /* … */ },
  get: function (id) { /* … */ }
};
```

规则：

- `find` / `measure`：采分点数组，自评时逐项勾选；得分 = 勾选数 / 总数。
- `calc`：`answer` 支持单空（`{value, tol}`）或多空数组；判定 `Math.abs(输入 - value) <= (tol || 0.01)`；全对得满分，否则 0（不设部分分，避免误导）。
- 案例得分 = 各题得分均值，四舍五入；`stats.case.best` 取历史最高。
- 题目 id 全局唯一；`ch` 必须落在 1-24。

## 页面流程

1. 入口：游戏厅新增「训练」区块（独立于 5 款小游戏），点「案例分析」进入 `#case`；同时路由表加 `"#case": "case"`。
2. 选择页：领域分组卡片，显示案例数与该领域最佳分；点击进入案例。
3. 答题页：背景常驻折叠区 + 逐题作答。
   - 主观题：`textarea` 输入自己的答案 → 展开采分点清单自评 → 显示参考答案/解析。
   - 计算题：数值输入 → 「判定」→ 正确/错误 + 步骤解析。
4. 可选 AI：主观题作答后出现「AI 批改」按钮（仅配置后可见），返回 `{score, hit[], miss[], advice}`；失败 toast 提示并保留自评入口。
5. 结算页：案例得分、各题得分、最佳分、重做/返回。

## AI 批改方案

- 存档键：`gaoxiang_ai_config`（独立 localStorage，不写入主存档；导出备份不含密钥）。
- 字段：`{ baseURL, model, apiKey }`（`baseURL` 默认 `https://api.openai.com/v1`）。
- 请求：`POST {baseURL}/chat/completions`，`messages` 含系统提示（高项案例阅卷人，按采分点给分，只输出 JSON）与用户内容（背景 + 题目 + 参考答案要点 + 学员作答）。
- 超时：`AbortController` 30s；非 2xx / JSON 解析失败 / 网络错误 → 返回 `null`，UI 降级为采分点自评。
- 隐私：档案页配置区明确提示「密钥仅存本机，请求将发往所填服务」；未配置时零网络请求。
- 不把任何 AI 返回结果写入存档（只在当前会话展示）。

## 存档扩展

```js
stats: {
  // 既有字段不变
  case: { attempts: 0, best: 0 }
}
```

`load()` 中补 `this.data.stats.case = this.data.stats.case || { attempts: 0, best: 0 }`；不新增 `save.version`。

## 测试计划（test-v2-m1.mjs）

- 数据：≥20 案例、10 领域每域 ≥2、id 唯一、ch 1-24、每题 type 合法且含 points/answer/exp。
- 判定：calc 精确值/容差内/容差外；多空题；find 采分点得分换算。
- 存档：完成案例后 `attempts+1`、`best` 取最高；旧存档补全不报错。
- AI：未配置时 `GX.ai.ready()===false` 且不发起请求；mock fetch 失败时 `grade()` 返回 null；配置存独立键，主存档序列化后不含 apiKey。
- 注册/路由：`#case` 可路由；游戏厅入口存在；`GX.gameList` 仍为 5 项（旧测试不破坏）。

## 验收标准

1. 游戏厅可见「案例分析」入口，`#case` 页面正常，控制台零错误。
2. 十大管理领域各 ≥2 案例，找错/措施/计算三类题均可完成并出分。
3. 计算题判定正确（含容差），错误时展示步骤。
4. 未配置 AI 时无网络请求；配置后主观题可 AI 批改，失败可降级自评。
5. `stats.case` 正确累计，旧存档兼容；四套既有测试 + 新增测试全过。
6. 公网重新部署成功。
