## 关键实现决策

- **解锁双通道**：Boss 通关立即解锁下一章；未打 Boss 但前章掌握度 ≥60% 亦可解锁。设计文档的「Boss 通关解锁」为主路径，掌握度通道保住 M2 用户的既有进度
- **Boss 战形态**：限时测验而非怪物战斗（与考点歼灭差异化）：总倒计时 + 题号进度 + 每题即时判定；时间到或答满 30 题即结算；提前交卷
- **通关加成**：`mastery = min(100, mastery + 10)`，只在首次通关时加
- **游戏战绩**：`stats.games = {monster/itto/match/chain/boss: {plays, best}}`，best 按 S>A>B>F 排序；旧存档由 load() 补默认
- **导入格式**：JSON 数组 `[{ch,q,opts:[4],ans:0-3,exp,diff?,tags?}]`（id 可省略自动生成）；同 id 跳过；合并后 byChapter/get 自然可见；自定义题不落盘到 bank.js
- **错题分型**：按 id 前缀分类（`c\d+`=单选 / `itto`=卡片 / `fl`=流程）；match 翻牌不收录（无稳定 id 且玩法本身即复习）
- **每日任务**：维持 M2 规则不变；三题型清扫均记 `review` 任务
- 保持零依赖、file:// 直开、save.version 仍为 1（新增字段走默认补全）

## 验收标准

1. 双击 index.html 可用；24 章每章 ≥30 题，全库 ≥740 题
2. Boss 战：30 题/25 分钟/及格 60%，通关加掌握度 +10 并解锁下一章；地图显示 CLEARED 徽标
3. 档案页：24 章掌握度全景 + 五款游戏战绩（局数/最佳评级）
4. 导入 JSON 自定义题后，章节选择/地图题数即时增加，清除后还原
5. ITTO 分拣答错、流程接龙有失误 → 错题本出现对应条目，分题型清扫可推进/回落记忆度
6. node 测试全过（含 ch11-24 数据完整性），浏览器实测无控制台错误
7. git 提交并重新部署公网
