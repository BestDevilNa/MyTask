## 3. 分项方案

### V2-A 论文练习器（P0）

目标：把论文从「无法自练」变成「可计时、可自评、可对照骨架」。

范围：

1. 论文题题库 `js/data/essay-data.js` → `window.GX_ESSAY = { topics:[...], samples:[...] }`
   - topic：`{ id, ch, title, request[], outline[], points[] }`（题目、要求、提纲、采分点）
   - 覆盖 24 章，每章 ≥2 题（十大管理领域优先）
2. 练习器页面 `#essay`（导航第 6 项）
   - 选题 → 倒计时（默认 120 分钟，可配）→ 大文本编辑区 → 实时字数统计
   - 草稿自动存 localStorage（独立键 `gaoxiang_essay_draft`，按 topic 分开），支持继续/重写/清空
3. 自评清单
   - 维度：切题、摘要、结构、理论引用、项目实践、字数；每项 0-5 分
   - 汇总总分 + 档位建议 + 对照采分点高亮缺失项
   - 结果写入 `stats.essay = { attempts, best }`
4. 范文卡：骨架 + 采分点段落示例（不做整篇范文堆砌，避免背模板）
5. 每日任务可选挂接：完成一次论文练习记一笔（不改变「≥3 项打卡」主规则，先只入统计）

验收：

- 离线可用；刷新/关闭后草稿还在；字数统计正确
- 24 章均有题，自评能出分并落存档
- 旧存档无 `stats.essay` 时不报错

待定决策：导航第 6 项 vs 放进游戏厅入口（倾向新增「论文」导航项）。

### V2-B 案例分析练习（P1）

目标：覆盖案例分析的「找错 / 措施 / 计算」三类题。

范围：

1. 案例题库 `js/data/case-data.js` → `window.GX_CASE`
   - `{ id, ch, bg, questions:[{ type:"find|measure|calc", q, points[]|answer, exp }] }`
2. 主观题：采分点自评勾选（逐点给分），展示参考答案与解析
3. 计算题：数值输入自动比对（允许误差区间），错解给步骤提示
4. 可选 AI 批改（默认关闭）
   - 用户在档案页填 OpenAI 兼容 `baseURL / model / apiKey`，存独立 localStorage 键
   - `fetch` 直连，超时/失败自动降级为采分点自评
   - 明确提示：密钥仅存本机、请求会发往所填服务
5. 结果入 `stats.case = { attempts, best }`

验收：

- 纯离线路径完整可玩（自评 + 计算判定）
- 未配置 AI 时无任何网络请求
- AI 失败不阻塞、不丢作答

待定决策：是否引入 API key 方案，或只做离线自评。

### V2-C 卡牌收集层（P2）

目标：给现有对局加一层收集反馈，不改核心数值平衡。

范围：

1. 卡池 `js/data/cards-data.js` → `window.GX_CARDS`（按知识域/章节，稀有度 N/R/SR）
2. 掉落：每局结算按评级给卡（S 必得 SR 碎片，A 得 R，B 得 N；重复转碎片）
3. 图鉴页：收集率、按章节分组、未获得剪影
4. 轻量效果仅限「对局外」：如展示用称号、首页看板装饰；**不做战斗数值 buff**，避免破坏掌握度与 SRS 语义
5. 存档扩展：`cards:{ owned:{id:count}, shards }`，默认补全

验收：

- 任意对局结算后按规则掉落并落盘；重复卡正确转碎片
- 图鉴收集率与 owned 一致；旧存档兼容
- 不影响既有掌握度/错题/每日任务逻辑（node 回归全过）

待定决策：是否允许碎片兑换指定卡（会影响长期留存，建议 V2 先不做）。

### V2-D 多设备云同步（P2）

目标：在「导出/导入 JSON」之上提供可选的自动同步。

范围（按推荐顺序）：

1. 基线增强（零后端，必做）：导出文件名带时间戳；导入时展示存档摘要（日期/题量/连胜）并二次确认覆盖
2. WebDAV 同步（可选）：用户在档案页填地址/账号/应用密码，手动「上传 / 下载」，冲突按 `updatedAt` 新者胜，下载前自动本地备份
3. Gist 同步（可选，二选一即可）：GitHub PAT + Gist ID
4. 不做自建后端、不做后台自动轮询

验收：

- 未配置时行为与现状完全一致
- 上传/下载成功后有明确时间戳提示；失败有可读错误且本地存档不受影响
- 冲突时不静默覆盖，保留可回滚备份

待定决策：WebDAV（坚果云）优先，还是仅保留手动导出/导入。

## 4. 推荐里程碑拆分

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| V2-M1 | V2-A 论文练习器（数据 + 页面 + 自评 + 草稿） | 无 |
| V2-M2 | V2-B 案例分析（题库 + 自评 + 计算判定；AI 可选后置） | 无 |
| V2-M3 | V2-C 卡牌收集层 + 档案页扩展 | 存档结构冻结于 M2 后 |
| V2-M4 | V2-D 同步增强（基线必做，WebDAV 可选）+ 全量回归与发布 | M1-M3 存档字段定型 |

每期固定动作：#1 数据 → #2 玩法/页面 → #3 测试 → #4 部署；沿用 test-*.mjs 断言风格。

## 5. 通用风险与对策

| 风险 | 对策 |
|---|---|
| localStorage 5MB 上限 | 论文草稿按篇限制长度并提示导出；卡牌只存 id+数量 |
| AI 接口跨域/密钥泄露 | 默认关闭、明确告知、失败降级；不写入主存档 |
| 云同步冲突覆盖 | `updatedAt` 比较 + 下载前本地备份 + 二次确认 |
| 收集层破坏数值平衡 | 卡牌仅展示，不参与战斗与掌握度计算 |
| 内容工作量（论文/案例题库） | 按章分批交付，先十大管理领域后其余章节 |
