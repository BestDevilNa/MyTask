## 关键实现决策

- **注册表驱动**：新游戏不再各自硬编码入口，`GX.gameList` 统一供 arcade/今日页/每日任务使用；后续 M3 Boss 战只需注册一条
- **新游戏错项不入错题本**：M2 错题本仍只收 single 题（monster/错题清扫闭环不破坏）；itto/match/chain 的错项仅计入 `GX.stats` 章节统计与掌握度。按题型分发复习是 M3 候选优化
- **每日任务轮换**：`dayIndex = 天序号 % 3` → [itto+match, match+chain, chain+itto] 三组合轮换，保证每日 4 项上限（monster + review? + 轮换 2 款）；打卡线恢复「≥3 项」（spec §4），每日任务面板显示 x/4
- **解锁规则（Boss 战前的 M2 适配）**：CH.n 掌握度 ≥60% 且有题库 → CH.n+1 可挑战；M3 上 Boss 战后切换为「Boss 通关解锁」
- **数据文件拆分**：ITTO/术语/流程数据量约 1.5k 行，独立成 itto-data.js / terms-data.js（spec 原架构并入 meta.js，此处按体量拆分，仍是普通 script 全局变量，不破坏 file:// 约束）
- **ITTO 卡片结构**：`{ id, domain:"风险", process:"识别风险", card:"风险登记册", cat:"input|tool|output" }`，按知识域分组；游戏局内同过程卡片优先混排
- **术语对结构**：`{ ch, pairs:[["CPI","成本绩效指数"],…] }`；**流程结构**：`{ id, name:"变更控制", steps:[…] }`（数组顺序即正确答案）
- 保持零依赖、file:// 直开、localStorage 单键存档；save.version 仍为 1，新增字段走 `store.load()` 默认补全

## 验收标准

1. 双击 index.html 可用（Chrome/Edge），4 款游戏均可开局且无控制台报错
2. ITTO 分拣 60s 计时准确、错拣扣时；术语配对 8 对 4×4 可完成；流程接龙错序重置当前步
3. 每日任务显示当日 4 项（含轮换游戏），完成 ≥3 项打卡、连胜推进；今日页无「M2 上线」锁态
4. 街区地图 CH.4-10 正确显示解锁门槛与掌握度，链式解锁生效
5. 题库 ch1-10 每章 ≥30 题；node 数据自检全通过
6. 手机 375px 与桌面 ≥768px 三款新游戏布局正常
7. git 提交并重新部署到公网站点
